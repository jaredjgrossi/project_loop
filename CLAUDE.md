# Loop — NYC Run Builder

Loop turns a plain-English run request ("6 mi loop from Kips Bay, mostly waterfront, I wait at lights") into real routes, scored with NYC data, shown on an iPhone app. Start with `README.md`; the reasons for every choice are in `docs/decisions/` (one note per decision, numbered); the API contract is `docs/phase3/parse-contract-v1.md`; setup is `docs/SETUP.md`. The original plan is `docs/PROJECT_PLAN.md`: its phases 0–3 are built, and its frontend became the iPhone app rather than the web app it describes; deploy, auth and PostHog (its phase 5) are not built.

## Non-negotiable product rules
1. **The LLM never generates geometry or numbers.** Claude only (a) parses requests into the `RunConstraints` schema and (b) answers whether the words name a place outside New York. Route explanations, names and all runner-facing copy are written by code. All routing and scoring is deterministic code.
2. **Every amenity, fact and scored value carries a source and a trust word**: `measured`, `estimate`, `listed`, `verified`, or `not scored`. Never show one without it.
3. **Say when a limit can't be met.** Return the nearest alternative and how far off it is. Never quietly relax a limit.
4. If parsing fails validation, return a clarifying question. Don't guess.

## Stack
- **iPhone app** (`/ios`): SwiftUI, iPhone only, iOS 17+, Mapbox Maps. The project is generated by XcodeGen from `ios/project.yml`. Signed with a free Personal Team for now (installs last 7 days). The Mapbox public token and the server's base URL come from the git-ignored `ios/Config/Secrets.xcconfig`; the Loop token is pasted into the app and kept in the Keychain.
- **API** (`/api`): FastAPI + Pydantic v2, Python 3.12, managed with `uv`. `POST /v1/runs` streams server-sent events (`parsed`, `candidates`, `top3`, `provisional`, `final`, `planned`, `done`, or `error`); stored routes, feedback, favorites, GPX and a city weather line have their own endpoints. One shared bearer token (`LOOP_TOKEN`) guards everything but `/v1/health`.
- **DB**: Postgres 16 + PostGIS in Docker (SRID 4326 for storage; project to EPSG:2263, NY State Plane in feet, for distance and area math).
- **Routing**: self-hosted GraphHopper in Docker, NYC OSM extract, `foot` profile with custom models (`/routing`), flexible mode (no CH or LM).
- **LLM**: Anthropic API with tool use, Claude Haiku 5.5 by default, two calls, both in `api/parse.py`: the parse and the outside-New-York check. Prompts live in `api/prompts/`, versioned (`parse_v1`…`parse_v7`, `area_v1`); a new prompt is a new file, never an edit to an old one. Route names and the reason line come from `api/naming.py` and `api/reason.py`; every can't-do line, question and error the runner reads comes from `api/copy.py`.
- **Where it runs**: the server runs on the owner's Mac for now (`make up` + `make serve`), and the phone reaches it over a private network. Hosting is undecided: there is no API container, no deploy and no public address. Don't describe one as if it existed.
- **Analytics**: none yet. The plan named PostHog; nothing in the code sends anything to a third party.
- **CI**: GitHub Actions runs the Python unit tests on every push and PR (decision 019). The evals and the iOS tests are not run in CI.

## Layout
```
/api        FastAPI server, parser and Claude client, route generators, scoring and ranking, GPX
/api/prompts  versioned prompts
/api/scripts  ask.py (send a request without the phone), make_loop.py, ui_fixture.py
/ios        the iPhone app (Loop/, LoopTests/, LoopUITests/, project.yml); see ios/README.md
/routing    GraphHopper config, custom models, no-go zones, curated closures
/etl        scripts that load NYC Open Data + OSM into PostGIS (places, landmarks, corridors, closures, crowds, pulses)
/evals      parse evals (live Claude) and route, place and crowd evals (live stack)
/ci         the pytest plugin that blocks network access in CI
/docs       plan, setup, discovery notes, decisions/, phase3/ (contract, parse evals, build brief), ui/
```

## Commands
- `make setup` once (Python deps, NYC map, services, data), then `make up` to start Postgres + GraphHopper and `make down` to stop them. `make help` lists the data reloads.
- `make serve` runs the API on 127.0.0.1:8000 (needs `make up` and `LOOP_TOKEN` in `.env`).
- `uv run pytest` runs the unit tests; `uv run pytest -p ci.no_network` runs them as CI does.
- `uv run pytest evals/` runs the live evals (needs the stack up and the data loaded; parse evals need `ANTHROPIC_API_KEY`).
- `make eval-parse PARSER=api.parse:parse` runs the 63 parse cases against live Claude and prints a table.
- `uv run python -m api.scripts.ask "6 mi loop, mostly waterfront" --at kips-bay` sends a request to the running API and prints the stream.
- `cd ios && xcodegen` regenerates `Loop.xcodeproj` (git-ignored) after editing `project.yml`; the test command is in `ios/README.md`.

## Conventions
- Write tests first for anything geometric (distance, share-of-route, near-mile-X lookups).
- Log tokens and cost for every Claude call into the `llm_calls` table.
- Record each architecture choice as a short note in `docs/decisions/NNN-title.md`. Check the highest number on `main` and on open branches before picking one.
- The 30 pinned top-3 rows (`evals/routes/test_pinned_top3.py`) change only on purpose: a change to ranking or generation that moves them is re-pinned in its own commit with a decision note saying why.
- The app shows only the trust words the route file gives it; it never makes one up.
- Keep each phase shippable; don't start v2 (tours) work until asked.
- Secrets stay out of git and out of the app bundle: the Claude key and `LOOP_TOKEN` live in `.env`, the Mapbox token and server URL in `Secrets.xcconfig`. Never write the private server address into a committed file.
- Starts in tests, evals, docs and screenshots are public stand-ins (`evals/routes/starts.json`, e.g. the Kips Bay Library), never a real home.
- Personal run data (`apple_health_export/`, `data/`) is git-ignored and never committed. Trim the first and last 200 m of any real route before storing or rendering it (decision 011). The runner's own history shapes routes only for the install ids in `LOOP_PRIOR_INSTALL_IDS` (decision 046).
- One branch and one PR per piece of work, targeting `main`; Jared merges.
